# 唯一后台容量实现

日期：2026-10-18。实现及验证完成，详见 [验证报告](outbox-single-capacity-report.md)。用户确认只保留后台方式，并要求删除双模式结构及无用逻辑。此规格取代实验规格中的运行模式选择和切回锁定模式方案；历史性能数据继续作为对照证据保存。

## 需求与方案

- 生产准入统一使用后台一致性快照与进程内临时预留；容量不足或快照过期时可取消等待。不再提供模式或等待开关。
- 删除容量计数行的锁、增减、核对及事务外重试。容量限制只属于准入层，存储和发布接口不再传递容量参数。
- 完成事件与请求汇总共用保存事务，保留事件摘要去重、并发重复写保护、应用身份校验、交付凭据去重、预留转换和执行阶段更新。已获准请求完成、取消补偿及消费释放不等待新容量。
- 开发内存存储只保留账本和 attempt 数量/字节上限，不维护无人读取的预留计数。
- 压测入口只执行后台方式，拒绝复用旧双模式测试二进制。历史结果读取器仍可解析已有对照数据。

## 显式迁移

容量协议升级为 2，计量协议固定为 3。运行时只检查版本，不执行 DDL。迁移删除旧 `gw_metering_capacity` 表和协议表的 `mode` 字段，保留账本、attempt、Outbox 和财务数据。

已有部署必须停写、排空、等待至少 5 秒心跳退出，并设置 `GW_METERING_MIGRATION_ACK=writers-stopped`。prepared/inflight、待补偿、剩余预留、未交付或旧非零容量计数均阻止迁移；未知费用不能清零。新空库可直接初始化，已完成迁移可重复执行。

MySQL DDL 隐式提交，因此先在控制行保护下写入容量版本 0，提交后执行可重复 DDL，最后写版本 2。版本 0 阻止新旧后台服务通过启动检查；DDL 中断后须保持停写并重跑 migrate。计量协议始终保持 3，避免重跑时触发旧账本导入。

## 验收

Go 测试、vet、构建、Linux race；真实 MySQL 的旧部署升级、停写与排空拒绝、版本 0 恢复、迁移幂等、未知版本拒绝、表与字段删除；真实 Redis/Kafka/etcd 下的满额等待取消、恢复准入及最终核账。验证后提交并更新 PR，记录实际结果。现有服务器仍是此前版本，不能将本次本机验证表述为已升级线上。
