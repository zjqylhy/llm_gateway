# 厂商凭据管理需求与方案

2026-10-12，用户反馈厂商凭据无法明确新增，并确认按现有“已保存模型”的展示方式修复需求和技术方案。

## 需求

- 厂商凭据以“已保存厂商”独立列表展示，包含编号、厂商类型、API Base URL、密钥保存状态；每行提供编辑操作，列表提供明确的“新增厂商”入口。
- 新增和编辑使用独立对话框。新增打开空白身份和密钥字段，必须填写新的编号及 API Key；编辑标题明确显示当前厂商，编号不可修改，密钥留空保留原密钥。
- 新增重复编号必须明确拒绝，不能覆盖原凭据。保存后刷新厂商列表及模型表单可选厂商。
- 保存失败保留表单并显示错误；取消不保存；密钥不回填、不显示在列表中，保存或关闭后清理前端表单密钥。
- 本次不增加厂商删除功能。初始页面不直接展示编辑表单，厂商与模型资源使用一致的列表、按钮及对话框布局。

## 技术方案

- 提取 `ProviderResources` 组件，和模型组件共用原生对话框，保留焦点约束及键盘关闭行为。
- `POST /admin/providers` 仅新增；重复编号返回 409。`PUT /admin/providers/{id}` 仅修改存在的厂商，不存在返回 404，路径和正文编号不一致返回 400。
- 复用现有管理员权限、CSRF、配置事务、审计和发布流程。新增检查密钥必填，编辑保留既有密钥；新增/编辑均继续验证厂商类型、编号及 URL。
- 从配置读取厂商时仅复制 id、kind、url 到表单，不提交只读的 secret 字段；后端仍拒绝未知字段。
- UI 新增与编辑分别采用 POST/PUT，提交失败在对话框显示具体错误。厂商密钥仍使用现有加密保存及脱敏读取机制。

## 验收

- 后端回归覆盖新增、重复新增不覆盖、编辑时保留或更新密钥、编号校验、不存在厂商、密钥必填、权限和 CSRF、发布失败仍保存、脱敏读取和失败不更改配置。
- Go 全量测试、静态检查、构建；前端构建、现有测试、格式检查及浏览器新增/编辑/取消验证通过后提交 commit。
- 与模型资源管理改动一并提交 PR，代码及验证结果交付用户确认；本次补充尚未授权云端版本切换。

- Go 全量测试、vet、build 通过，部署静态校验通过（30 份 YAML、38 个监控面板）。新增后端回归验证新增/重复新增、编辑保留和更新密钥、空白密钥、编号与存在性、权限和 CSRF、加密与脱敏读取、审计及发布失败仍保存。
- 前端 TypeScript / Vite 构建、16 项现有测试、格式检查通过。
- 隔离离线服务的浏览器验证：新增为空白表单且密钥必填；保存后列表由 3 个变为 4 个；编辑编号只读且密钥不回填；留空密钥修改 URL 保存成功；新增模型下拉出现新厂商；重复编号明确拒绝且不覆盖；取消修改后原 URL 保留；共享对话框的新建模型表单正常。
