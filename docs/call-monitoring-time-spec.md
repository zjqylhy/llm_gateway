# 调用监控恢复与调用时间展示

2026-10-13，用户确认需求与技术方案后实施。

## 问题与范围

云端 Prometheus 抓取正常，最近一小时已有成功及失败调用；管理端拒绝历史 `http_error / HTTP 200` 组合，导致成功、失败和上限曲线一起清空。该组合由请求上下文取消时的兜底分类产生。调用审计及应用概览的近期调用共用列表组件，接口已有 `at`，页面尚未展示。

## 修复方案

- 将未带业务错误码、HTTP 200 的上下文取消归类为固定错误码 `client_canceled`，继续按失败计数，保持每次客户端调用只统计一次。
- 兼容既有 `http_error / 200` 及兜底 HTTP 400–599 组合；其他已知业务错误码继续校验对应状态，拒绝未知代码、非法状态、重复序列及越权应用。不改写历史采样，不用审计记录代替监控。
- 共用调用列表增加“调用时间（北京时间）”，使用 `at` 展示年月日与时分秒，固定 Asia/Shanghai 时区；缺失、非法或零值时间显示“未提供”，原始时间供悬浮查看。请求汇总为请求开始时间，实际调用为对应尝试开始时间。
