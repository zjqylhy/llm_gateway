# 应用路由、审计溯源与控制台视角

## 已确认需求

2026-10-12 用户确认需求和技术方案。先同步远端 master，再在独立分支实现。

- 应用可覆盖全局模型别名的候选、策略、降级与灰度；未覆盖的别名继承全局。
- 调用审计展示应用名称、ID、请求链路及实际路由来源。新记录保存应用名称、策略和配置版本快照；旧记录仍按 ID 识别，不改写历史事件或哈希。
- 应用概览展示业务计量摘要；网关运维独立展示实例、全局控制状态、配置同步及核验历史。

## 技术方案

- `Config.app_routes[app_id][alias]` 存储完整覆盖，允许覆盖应用获授权的全局别名且类型一致。覆盖没有可用候选时拒绝，不偷偷回到全局。Chat、Embedding、Rerank 共用解析逻辑。
- 应用路由读接口受应用权限保护；保存、删除覆盖及灰度管理仍仅管理员。删除覆盖恢复继承。模型修改同时校验全局和应用配置。
- 灰度样本、运行 ID 和自动回滚按路由作用域隔离；全局样本包含实际继承全局的请求。配置保存重新分配运行 ID，防止旧样本影响新策略。
- 审计快照字段可选，保持旧事件序列化兼容。详情查询携带记录自身应用 ID，应用改名不覆盖调用时名称。
- 新增业务计量摘要读接口，按应用授权和筛选返回状态、影响、最近核验结果与时间；不返回内部恢复代次、错误载荷或实例。未知、未核验和离线模式明确展示，不伪装正常。全局冻结会反映到每个应用。
- SQL 控制正常时还读取计量许可；许可失效或无法确认时显示计量暂停，不把实例心跳正常当作可新增付费调用。
- 管理员运维页保留详细计量接口；实例区分在线、心跳过期及配置未同步，默认折叠历史实例。新增心跳标识包含服务角色，兼容旧标识为未知角色，不需迁移表。
- 应用路由与计量摘要读取向开发者开放本人应用，成本角色按现有报表权限可读；写权限不扩展。控制台按业务与运维分组，保留现有流量图和失败下钻。

## 验收

- 两应用使用同一别名命中不同候选，继承、删除覆盖、候选失效和越权操作行为正确。
- 灰度样本与回滚隔离，旧运行不影响新运行；模型更新不会使覆盖配置无效。
- 审计来源贯穿成功、重试降级、流式、缓存与内部调用；旧记录仍能查询且序列化不变。
- 业务计量按应用筛选并授权，核验时间和全局冻结影响正确；业务页不读取运维接口。
- 心跳过期与配置未同步独立展示，历史实例折叠；应用选择与请求详情不串应用。
- 完成 Go 测试、vet、build，前端测试、构建和格式检查及部署配置验证；提交 commit 后交付用户确认代码及测试结果。

## 接口与兼容

- `GET /admin/apps/{id}/routes`：应用授权别名的策略、来源及配置版本。
- `PUT /admin/apps/{id}/routes/{alias}`：保存完整覆盖；`DELETE` 同路径恢复继承。
- `POST /admin/gray-release`：可选 `app_id` 指定应用；省略仍管理全局。
- `GET /admin/app-metering?app_id=...&after=...`：业务摘要；省略应用则分页返回角色可访问应用，每页最多 100 项。
- `/admin/instances` 与 `/admin/metering` 保持管理员权限，实例响应新增服务角色、心跳年龄及独立状态。
- 新事件增加可选 `app_name`、`route_scope`、`route_strategy`、`config_version`；内部缓存向量化来源为 `internal`。
- 配置和事件继续使用现有 JSON 列，不需要数据库 DDL。发布时 gateway/admin/worker 应使用同一版本，旧消费者会忽略新增事件字段。本次只交付本地代码，部署另行授权。
