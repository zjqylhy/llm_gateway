# 唯一后台容量实现验证

日期：2026-10-18。规格见 [需求与方案](outbox-single-capacity-spec.md)。

## 实现

- 删除模式与等待开关、同步容量锁及增减计数、锁定模式重试和回退实现。
- 准入固定后台采样与本地预留；应用上限由当前配置读取，存储和发布层不再传递容量上限。
- 合并完成与汇总的 Outbox 保存事务，删除为绕开全局锁而重复的完成保存路径。先核对事件，再锁 attempt 并复查并发保存/交付；新事件插入成功后才转换预留。无 attempt 的请求汇总通过唯一键和摘要处理并发重复。
- 删除开发内存存储的预留累计与无效写回，保留数量和账本字节上限。
- 显式迁移到容量版本 2、计量版本 3，删除旧计数表与模式字段。中断状态标记为版本 0，停写重跑可恢复；旧非零计数和未排空状态会阻止删除。
- 压测脚本仅运行后台方式，二进制复用只接受版本 3 驱动。历史分析器仍能读取此前对照报告，不提供旧模式执行入口。

独立快速验收 `gw_capacity_c6de79be8fa7` 用时 32.60 秒，辅助验收 `gw_capacity_86d4b534455c` 用时 105.27 秒，使用随机隔离的 MySQL/Redis/Kafka/etcd 和两个网关。最终辅助验收覆盖交付版本；脚本最终逐应用对照 SQL 与 Redis 的 Token、费用、预留，均通过。随机容器和卷已清理。

本次是功能与简化回归，没有重新标定最大可接受 QPS。快速验收的 20 QPS 样本不满足此前性能阈值，不能把测试整体通过表述为这一档性能达标。此前多档位性能报告保留原代码及实验条件，不将旧数据归为本次结果。

首轮本机 Go 测试受沙箱本地套接字限制失败，允许访问 mock 后通过。首轮基础设施运行因 Docker 未启动而未执行，恢复 Docker 后重跑通过。
