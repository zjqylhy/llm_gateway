# 配额存储实验结果

2026-10-11，最终实验 `gw_quota_491965d693b7`，运行约 171 秒。实验与研究代码仅用于验证，不改变生产运行时、配额数据或既有容器。

## 实验方法

详见 [实验 spec](quota-comparison-spec.md)。独立 MySQL 8.4 和 Redis 7.4 容器均限制 1 CPU；MySQL 容器 1GiB、buffer pool 128MiB，Redis 容器 512MiB、maxmemory 128MiB。MySQL `innodb_flush_log_at_trx_commit=1`、`sync_binlog=1`；Redis AOF/appendfsync always、noeviction。MySQL 连接池 30，Redis 32，客户端为 Windows Go。依赖与客户端经 Docker Desktop loopback 通信，其他本地项目继续运行，不能视为独占机器实验。

对比的是一次付费 attempt 的存储周期：预占、started 入账、completed 入账与结算。两种方案均写相同的 MySQL 事件及最新账本；MySQL 基线把 completed 入账与配额结算放在一个 READ COMMITTED 事务，Redis 方案复用生产 Guard 并在 MySQL 入账后执行结算 Lua。SQL 基线是测试代码，不具备生产切换、历史迁移和完整故障恢复能力。

每个工况 3 秒，预热 32 次，重复 3 轮，轮换两方案顺序。总计 36 组采样，1/32 应用均匀分配，1/16/64 并发。循环完成吞吐计入最后在途请求耗时；P99 只统计成功周期，失败率另列。表中吞吐及 P99 是三轮指标的中位数，不是合并样本的分位数。

## 解读与建议

- 单应用并发集中时，MySQL 月度汇总行是竞争点；16 并发下 Redis 方案吞吐约为基线 5.5 倍。分摊到多个应用可显著减少行锁竞争。
- 多应用、16 并发时，MySQL 方案约快 10%，不能宣称 Redis 对所有负载都提升总吞吐。Redis 预占仍较快，完整周期还受共同账本写入、持久化和连接池影响。
- 当前数据支持暂时保留 Redis 配额，尤其考虑多网关实例同时向同一应用服务。小流量、应用流量分散时，MySQL 独立方案仍是降低运维和一致性复杂度的备选。
- 最终架构决定需补目标负载下的端到端、长时间与云网络实验，并比较 SQL 预占与 started 入账合并、批处理、汇总分片/额度分片及锁冲突重试等优化。当前基线没有这些优化，结果不能视作 MySQL 的性能上限。

本实验不包含 Kafka ACK、HTTP、鉴权、限流、真实上游、缓存命中、业务槽位、长报文及网络故障；64 并发是直接施加在存储层，超过默认单网关 16 槽。数据是短时本地实验结果，不是网关 RPS、SLO 达标或长期增长后的生产容量承诺。生产 MySQL 与 Redis 原有最终一致性和恢复要求依然存在。

## 复跑与证据

```powershell
./scripts/compare-quota-storage.ps1
```

脚本使用本地已缓存镜像创建随机名称、独立端口、专用标签和匿名卷的临时容器；创建随机测试凭据，不读取或修改生产凭据。结束后仅删除本次容器和卷，并清理临时 mysql.env。需要本机 Docker 与 Go。

完整脱敏采样结果已保存到 [quota-comparison-results.json](quota-comparison-results.json)，本机原日志为 `data/acceptance/gw_quota_491965d693b7/test.log`。JSON 同时保存失败、连接池等待、结算差额和残留预占，避免只保留有利结果。

前置失败与修订：

1. `gw_quota_445c4a872303` 在正确性预检查失败：SQL 初始化用 INSERT IGNORE 后升级锁导致死锁；改为直接获取排他锁的 upsert。
2. `gw_quota_ad853c8b8e50` 在单应用 64 并发因预占残留中止：测试错误地要求饱和组也无未完成预占；修订为保留错误和残留指标，继续完成采样。
3. `gw_quota_e3bf8a8b7285` 完成采样，但默认隔离级别在多应用组出现 attempt 插入间隙锁死锁；结果未用于最终性能结论。以 READ COMMITTED 保留汇总行排他锁后，完整重跑得到本文结果。有关隔离级别的依据见 [MySQL 文档](https://dev.mysql.com/doc/refman/8.4/en/innodb-transaction-isolation-levels.html)。

租户容量隔离与同类系统日志生命周期研究见 [storage-research.md](storage-research.md)，建议尚未实施。
