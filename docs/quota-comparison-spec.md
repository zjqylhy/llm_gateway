# 配额存储对比实验

状态：用户授权进行性能对比；实验基线仅存在于测试代码，不切换生产实现。租户隔离与归档方案待人工确认。

## 对比范围

- Redis：复用生产 RedisGuard，启用 ready、noeviction 和 90% 水位核验，AOF 每次写入 fsync。
- MySQL：测试专用配额表，READ COMMITTED 事务锁定应用月份汇总，再按 attempt/revision 幂等预占和结算；完成事件入账与配额结算合并为一个事务。汇总行是并发额度检查的串行化边界，避免不存在的 attempt 在默认隔离级别下产生间隙锁冲突。
- 两者均写入同样的 started/completed MySQL 账本；Redis 完成事件先入账再结算。
- 使用独立临时 MySQL 和 Redis 容器，均限制 1 CPU；MySQL 容器 1GiB、buffer pool 128MiB，Redis 容器 512MiB、数据上限 128MiB。记录 MySQL 持久化配置，不修改既有数据和服务。

## 负载与验收

并发 1/16/64，应用数量 1/32，每组 3 秒，重复 3 次，交替执行顺序。统计完成次数、完整存储周期吞吐和 P50/P95/P99、预占延迟、错误数、连接池等待。预热不计入统计；无错误组必须逐应用核对账本与配额且无残留预占。饱和组允许触发 1 秒操作超时，单独记录错误率、未释放预占和结算差异，不把失败算入成功吞吐或延迟分位数；实验完成不代表这些负载可用于生产。预先验证重复事件、递增修正和并发额度争抢。

完整周期为预占、started 入账、completed 入账与结算。Kafka、鉴权、模型调用、HTTP 和分布式网络不在本实验范围；结果不是网关 RPS、业务 P99 或云容量承诺。客户端运行 Windows，依赖运行 Docker Desktop，服务器与其他本地应用共享宿主资源。测试未优化 SQL 基线的批处理、预占分片和连接池，不能把单次实验当成最终架构结论。
