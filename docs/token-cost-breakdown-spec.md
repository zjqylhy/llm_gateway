# Token 与费用明细

## 确认与范围

2026-10-12 用户确认需求及方案：调用记录、请求追踪、成本汇总与 CSV 同步展示普通输入、模型缓存读取、输出和网关语义缓存的内部向量化用量及费用。保留总 token、总费用及待核实状态。代码与验证结果交付后等待人工确认。

## 计量口径

- 输入总量包含缓存输入；普通输入 = 输入总量 - 缓存输入；总 token = 输入总量 + 输出。缓存输入不得重复计入总量。
- 使用 attempt 的模型价格版本、原币种与汇率快照，展示人民币微单位费用。按普通输入、缓存输入、输出的累计金额向上取整后取差，三项之和必须等于现有 Cost 的总额，不改变配额结算与账本事件。
- 历史事件的快照无法还原账本金额、用量只有总量或仍在进行时，不编造费用分项。原总费用计入未分摊费用，计入对应记录数。
- 缓存读取用量缺失标记为未提供；明确返回零与未返回须区分。旧记录的非零缓存用量可以确认，旧记录的零不能证明上游明确返回过零。估算值保持估算标记。
- 网关语义缓存与模型缓存读取分开。语义缓存命中通过请求结果关联内部 cache_embedding attempt；向量化次数、token、费用属于报表现有总额中的子项，不额外累加。没有向量化事件时不虚构关联命中。
- 缓存写入、推理 token 当前没有完整计费适配，页面明确显示未提供；不另设单价，不把推理子项重复计入输出。
- failed/retry/fallback 均按各自 attempt 统计；修正取最新 revision；started 不作为零费用确认。取消且确认无消耗的 completed 可以为零。

## 技术方案

- Go 提供基于快照的费用拆分函数；管理端返回派生费用明细，不修改既有事件或历史载荷及其哈希。
- 内存汇总与 MySQL 聚合提供相同字段。MySQL 使用 JSON 快照和 DECIMAL 精确算术在数据库聚合，保留 10000 分组上限，不将全量账本传入进程。
- 前端展示分项用量及费用、价格版本和用途。CSV 保留原列并追加明细列。
- 不改动本次开始前已有的部署文档和监控配置修改。

## 验收

- 覆盖缓存读取、外币汇率、微额舍入、免费模型、历史总量记录、未提供缓存字段、进行中记录、修正及重复事件。
- 分项费用加未分摊费用严格等于总费用；内部向量化费用不重复累加；筛选及开发者应用授权保持有效。
- 验证 Go 测试与静态检查、前端测试及构建；MySQL 查询有独立集成用例，外部服务不可用时如实说明未运行。
