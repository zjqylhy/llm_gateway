# 2 核 4 GiB 个人部署验收报告

日期：2026-10-11。需求及技术方案见 [spec](lite-deployment-spec.md)，操作步骤见 [部署指南](lite-deployment.md)。

状态：代码回归及容器范围的 60 分钟 HTTPS 链路验收通过。首次持续验收失败后，更新 Kafka 官方补丁并重新完成测试，失败记录保留。本报告所述隔离验收未验证整机 2 核 4 GiB、阿里云或真实模型厂商；后续实际部署及小额度真实调用结果见[本地及阿里云部署记录](local-cloud-deployment-report.md)，仍未完成 ECS 持续负载容量验收。

## 已完成的改动

- 全局 `GW_CACHE_ENABLED=false` 时，不创建或访问 Milvus/缓存 Redis；worker 跳过向量维护，cache-init 明确退出。直接 Embedding API 保留。
- 旧应用缓存配置保持原值并全局绕过；管理接口拒绝新启用缓存，控制台显示关闭原因。默认完整模式仍启用缓存基础设施。
- SQL/Redis 池参数可配置并在启动时校验。低配使用 SQL 12/2、Redis 8；完整模式保持 30/10、32。
- 独立 Compose 使用三个 Go 角色、四个真实依赖和 Caddy；不启动缓存基础设施及独立监控平台。公开入口需要显式启用，备案前可用 loopback HTTPS 和 SSH 隧道。
- 提供本机交叉编译/打包、随机隔离验收脚本、域名与备案新手指南和可选备案号页脚。

## 系统盘建议

个人少量调用推荐 60 GiB；预算优先可从 40 GiB 起步。镜像标称大小合计约 2.4 GiB，持续验收中 MySQL/Kafka/Redis 数据卷在约 35 分钟时合计约 0.42 GiB。这不是长期容量测试，也未计入操作系统、Docker 层文件及更新期间的额外空间。部署时保留至少 20% 空闲，备份存放到另一位置；具体选择与扩容步骤见部署指南。

## 结果边界

- Docker Linux 宿主机为 32 CPU、约 15.18 GiB 内存；本轮设置的是单容器内存上限，没有整组 2 CPU / 4 GiB 约束，不能宣布整机容量通过。
- `docker stats` 数据为采样，可能漏掉短暂 CPU 峰值；cgroup v2 `memory.peak` 包括初始化和文件缓存，以及测试采样临时 Go 进程的开销。不同容器峰值不一定同时发生。
- 模型端为测试二进制中的可控上游。生产命令没有 mock/私网上游放行开关。真实厂商网络、TLS、费用、用量和限制未验证。
- 已测试本地 Caddy HTTPS，公网配置经过校验；实际域名解析、公网 ACME 签发/续期、备案和云安全组未执行。
- 仍需要独立 2 核 4 GiB Linux/阿里云实例验证整机内存、CPU、磁盘与真实厂商小额度调用，再判断该规格是否满足实际用途。
